<task type="auto">
  <name>Task 2: Create TwitterChunkedUpload module</name>
  <files>server/lib/clippster_server/social/twitter_chunked_upload.ex</files>
  <action>
Create `ClippsterServer.Social.TwitterChunkedUpload` module implementing the full X API v2 chunked upload workflow.

**Public API:**
`upload_video(access_token, video_binary, opts \\ [])` -- orchestrates the full flow, returns `{:ok, media_id}` or `{:error, reason}`.

**Module attributes:**
- `@upload_url "https://api.x.com/2/media/upload"` -- MUST use v2 endpoint, NOT v1.1 upload.twitter.com (deprecated March 2025)
- `@chunk_size 1_024_000` -- 1MB chunks (recommended by X, lower failure rate than 5MB)
- `@max_poll_attempts 60` -- ~5 minutes max polling
- `@http_timeout 30_000` -- 30 second timeout for INIT/FINALIZE/STATUS
- `@append_timeout 60_000` -- 60 second timeout for APPEND (larger payloads)

**upload_video/3 flow (use `with` chain):**
1. Call `VideoValidator.validate(video_binary, opts)` -- reject invalid videos early
2. Call `init_upload/3` with access_token, byte_size(video_binary), media_type from opts (default "video/mp4")
3. Call `append_chunks/3` with access_token, media_id, video_binary
4. Call `finalize_upload/2` with access_token, media_id
5. Call `poll_until_ready/3` with access_token, media_id, processing_info from finalize
6. Return `{:ok, media_id}`

**Private functions:**

`init_upload(access_token, total_bytes, media_type)`:
- POST to @upload_url with form-urlencoded body: command=INIT, media_type, total_bytes, media_category="tweet_video"
- Headers: Authorization Bearer, Content-Type application/x-www-form-urlencoded
- Parse response for "media_id_string" (use string version, not integer)
- Return `{:ok, media_id}` or `{:error, {:init_failed, status, body}}`

`append_chunks(access_token, media_id, video_binary)`:
- Split binary into @chunk_size pieces using `:binary.part/3`
- Upload each chunk sequentially (NOT parallel -- X requires order)
- For each chunk, call `append_chunk/4` with segment_index starting at 0
- Return `:ok` or `{:error, reason}` on first failure

`append_chunk(access_token, media_id, chunk_binary, segment_index)`:
- POST to @upload_url with multipart/form-data body
- Multipart parts: {"command", "APPEND"}, {"media_id", media_id}, {"segment_index", "#{segment_index}"}, {:file, chunk_binary, {"form-data", [name: "media"]}, []}
- Headers: Authorization Bearer (do NOT set Content-Type -- HTTPoison sets it for multipart)
- Use @append_timeout for timeout options
- Return `:ok` on 200/202/204 or `{:error, {:append_failed, segment_index, status, body}}`

`finalize_upload(access_token, media_id)`:
- POST to @upload_url with form-urlencoded body: command=FINALIZE, media_id
- Headers: Authorization Bearer, Content-Type application/x-www-form-urlencoded
- Parse response: if "processing_info" key exists, return `{:ok, processing_info}`. If no processing_info, return `{:ok, nil}` (immediate success).
- Return error tuple on failure

`poll_until_ready(access_token, media_id, processing_info)`:
- If processing_info is nil, return `{:ok, :ready}` immediately (no async processing needed)
- Extract check_after_secs from processing_info, default to 5
- Call `do_poll/4` recursive function

`do_poll(access_token, media_id, wait_seconds, attempt)`:
- Sleep for wait_seconds * 1000 milliseconds using `:timer.sleep/1`
- GET @upload_url with query params: command=STATUS, media_id=media_id
- Headers: Authorization Bearer
- Match on processing_info.state:
  - "succeeded" -> `{:ok, :ready}`
  - "failed" -> `{:error, {:processing_failed, error_map}}` where error_map is from processing_info
  - "pending" or "in_progress" -> extract next check_after_secs (default to previous wait_seconds), recurse with attempt + 1
- If attempt >= @max_poll_attempts -> `{:error, :processing_timeout}`

**Logging:** Use `Logger.info` for INIT/FINALIZE/STATUS state changes, `Logger.debug` for APPEND progress (every chunk would be noisy). Log "[TwitterUpload]" prefix for all messages.

**Error handling:** Follow twitter.ex pattern -- parse JSON errors from response body, return structured error tuples.
