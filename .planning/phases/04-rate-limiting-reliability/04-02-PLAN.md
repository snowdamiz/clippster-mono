**Step 1: Create TwitterDuplicateDetector module** at `server/lib/clippster_server/social/twitter_duplicate_detector.ex`.

Module: `ClippsterServer.Social.TwitterDuplicateDetector`

Public functions:
- `check_duplicate(account_id, text, media_ids \\ [])` - Generate SHA-256 hash of `text <> Enum.join(Enum.sort(media_ids), ",")`. Query `post_submissions` where `content_hash == hash` AND `organization_social_account_id == account_id` (OR `user_social_account_id == account_id` to handle personal accounts) AND `inserted_at >= 24 hours ago` AND `status in ["published", "publishing"]`. If found, return `{:error, :duplicate_content, existing_post}`. If not found, return `{:ok, content_hash}`.
- `generate_hash(text, media_ids \\ [])` - Public helper that returns the SHA-256 hex digest. Uses `:crypto.hash(:sha256, content) |> Base.encode16(case: :lower)`.

Use `import Ecto.Query` for query building. Alias `ClippsterServer.Repo` and `ClippsterServer.Social.PostSubmission`.

The `@lookback_hours 24` module attribute controls the duplicate detection window.

**Step 2: Update Twitter module to use TwitterApiClient.**

In `server/lib/clippster_server/social/platforms/twitter.ex`:

1. Add alias: `alias ClippsterServer.Social.TwitterApiClient`

2. Replace ALL `HTTPoison.post(...)` and `HTTPoison.get(...)` calls with `TwitterApiClient` calls. Specifically update these functions:
   - `exchange_code/2`: Replace `HTTPoison.post(@x_token_url, body, headers, @http_options)` with `TwitterApiClient.post(@x_token_url, body, headers, endpoint: "/2/oauth2/token")`. Adjust pattern matching: TwitterApiClient returns `{:ok, %HTTPoison.Response{...}}` (it wraps HTTPoison), so the existing pattern matching should still work. Pass `http_options: @http_options` in opts.
   - `refresh_tokens/1`: Same replacement for the HTTPoison.post call. Use `endpoint: "/2/oauth2/token"`.
   - `get_user_profile/1`: Replace `HTTPoison.get(url, headers, @http_options)` with `TwitterApiClient.get(url, headers, endpoint: "/2/users/me", http_options: @http_options)`.
   - `create_tweet/3`: Replace `HTTPoison.post(@tweets_url, body, headers, @http_options)` with `TwitterApiClient.post(@tweets_url, body, headers, endpoint: "/2/tweets", http_options: @http_options)`.
   - `fetch_video_binary/1`: This downloads from R2/external URLs, NOT X API. Keep as `HTTPoison.get` (no retry/rate limit needed for non-X URLs).
   - Analytics functions (`get_tweet_analytics/1`): These use twitterapi.io, NOT the X API. Keep as `HTTPoison.get` (different rate limit domain).

Note: The `social_account_id` opt is not available in all Twitter module functions (e.g., exchange_code doesn't have an account yet). Only pass it when available. For functions called during publishing (create_tweet, publish_media), the caller in ScheduledPostWorker/PostSubmissionController should pass it through opts.

3. Do NOT change the TwitterChunkedUpload module in this plan - it has its own HTTP calls for media upload that can be addressed separately if needed.

**Step 2: Wire duplicate check into ScheduledPostWorker.**

In `server/lib/clippster_server/social/scheduled_post_worker.ex`:

1. Add alias: `alias ClippsterServer.Social.TwitterDuplicateDetector`

2. In the Twitter-specific `do_publish/3` clause (the one matching `%PostSubmission{platform: "twitter"}`), add duplicate detection BEFORE the media upload step:

```elixir
# Before existing media upload logic:
account_id = get_account_id(post)  # helper to get org or user social account id
media_ids = []  # pre-upload, no media_ids yet for hash - hash caption only at this stage

case TwitterDuplicateDetector.check_duplicate(account_id, post.caption || "", media_ids) do
  {:ok, content_hash} ->
    # Proceed with existing two-step publish flow
    # After successful tweet creation, store content_hash:
    # Update the post with content_hash via Social.update_post_content_hash(post, content_hash)

  {:error, :duplicate_content, existing_post} ->
    handle_publish_failure(post, "Duplicate content detected (matches post #{existing_post.id} from #{existing_post.posted_at})", :permanent)
end
```

3. After successful tweet creation (where `handle_publish_success` is called), also store the content_hash on the post submission. Add to the Social module a new function or update the existing `mark_post_published` call to include `content_hash` in attrs. The simplest approach: after `handle_publish_success`, call:
```elixir
Repo.update(Ecto.Changeset.change(post, content_hash: content_hash))
```
Or add content_hash to the publish_changeset attrs passed to `Social.mark_post_published/2`.

4. Add a private helper `get_account_id/1` that returns `post.organization_social_account_id || post.user_social_account_id`.

**Step 3: Wire duplicate check into PostSubmissionController.**

In `server/lib/clippster_server_web/controllers/post_submission_controller.ex`:

1. Add alias: `alias ClippsterServer.Social.TwitterDuplicateDetector`

2. In the Twitter-specific `publish_to_platform/3` clause, add duplicate detection BEFORE the media upload step, following the same pattern as ScheduledPostWorker.

3. On duplicate detection, return an error response to the client with a clear message: "This content has already been posted to X. Duplicate posts are not allowed within 24 hours."

4. After successful tweet creation, store content_hash on the submission (same pattern as ScheduledPostWorker).

**Important:** The duplicate check only uses caption text (not media_ids) at the pre-publish check stage, because media hasn't been uploaded yet. After publish, the content_hash stored should include the media_id for accurate future duplicate detection. So the flow is:
1. Pre-check: `check_duplicate(account_id, caption, [])` - catches text-only duplicates
2. After upload + tweet: `generate_hash(caption, [media_id])` - store full hash for future checks

This means a user COULD bypass the pre-check by posting same text with different media. That's acceptable behavior - X's duplicate detection considers media too, so different media = different content.
