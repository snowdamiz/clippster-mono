<task type="auto">
  <name>Task 1: Rewrite Twitter Platform module with OAuth 2.0 PKCE</name>
  <files>server/lib/clippster_server/social/platforms/twitter.ex</files>
  <action>
Rewrite the existing twitter.ex from twitterapi.io analytics-only to full Platform behaviour implementation for X OAuth 2.0 with PKCE. The existing analytics functions (get_tweet_analytics, extract_tweet_id, is_twitter_url?) should be preserved as additional public functions since they are used by the analytics system.

Follow the Instagram platform module pattern exactly (same structure, same error handling conventions, same PulseKit logging pattern).

Implement these Platform behaviour callbacks:

1. `platform_id/0` - Returns "twitter"
2. `platform_name/0` - Returns "X (Twitter)"

3. `authorize_url/1` - Takes opts map with :client_id, :redirect_uri, :scope, :state.
   - Generate PKCE pair using private `generate_pkce_pair/0`:
     - code_verifier: `:crypto.strong_rand_bytes(32) |> Base.url_encode64(padding: false)`
     - code_challenge: `:crypto.hash(:sha256, code_verifier) |> Base.url_encode64(padding: false)`
   - Merge code_verifier into state map before Base64 encoding
   - Build URL: `https://x.com/i/oauth2/authorize` with params: response_type=code, client_id, redirect_uri, scope (default: "tweet.read tweet.write users.read offline.access"), state (Base64-URL encoded JSON with code_verifier), code_challenge, code_challenge_method=S256
   - Return the authorization URL string

4. `exchange_code/2` - Takes code string and opts map with :client_id, :client_secret, :redirect_uri, :code_verifier.
   - POST to `https://api.x.com/2/oauth2/token` with form body: code, grant_type=authorization_code, client_id, redirect_uri, code_verifier
   - Authorization header: Basic auth with client_id:client_secret (Base.encode64)
   - Content-Type: application/x-www-form-urlencoded
   - On 200: Parse JSON, return {:ok, %{access_token:, refresh_token:, expires_in:}} (expires_in will be 7200)
   - On error: Return {:error, reason} with extracted error message
   - Use 30-second timeout like Instagram (@http_timeout 30_000)

5. `refresh_tokens/1` - Takes refresh_token string.
   - Read client_id and client_secret from Application.get_env(:clippster_server, :twitter_oauth)
   - POST to `https://api.x.com/2/oauth2/token` with form body: refresh_token, grant_type=refresh_token, client_id
   - Authorization header: Basic auth with client_id:client_secret
   - CRITICAL: On success, return {:ok, %{access_token: new_access, refresh_token: new_refresh, expires_in: expires_in}} -- the new refresh_token MUST be included because X uses single-use refresh tokens
   - On 401: Return {:error, :refresh_token_expired} (user must re-authenticate)
   - On other error: Return {:error, :refresh_failed}

6. `get_user_profile/1` - Takes access_token string.
   - GET `https://api.x.com/2/users/me?user.fields=profile_image_url,name,username`
   - Authorization: Bearer token
   - On 200: Parse JSON "data" key, return {:ok, %{user_id:, username:, display_name:, profile_image_url:}}
   - On error: Return {:error, reason}

7. `publish_media/3` and `get_insights/2` - Stub implementations returning {:error, :not_implemented} for now (Phase 2 and 3 will implement these).

Add private helper `extract_error/2` following Instagram's pattern.
Add PulseKit pulse_capture helper matching Instagram's pattern.
Preserve the existing analytics functions at the bottom of the module.
