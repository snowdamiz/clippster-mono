<task type="auto">
  <name>Task 1: Add admin-only website routes and access guard</name>
  <files>
    landing/src/components/AdminRoute.tsx
    landing/src/main.tsx
    landing/src/types/auth.ts
    landing/src/pages/dashboard/DashboardIndex.tsx
  </files>
  <action>
1. Add `AdminRoute` guard component that redirects unauthenticated users to login and non-admin/non-moderator users to `/dashboard`.
2. Register `/admin/*` and `/dashboard/admin/*` routes in `landing/src/main.tsx`.
3. Extend landing auth user type with `is_moderator` for parity with app route permissions.
4. Route admins/moderators from dashboard index to `/admin` as primary web destination.
  </action>
  <verify>
1. `landing` build passes (`yarn build`).
2. Non-authenticated access to `/admin/*` redirects to `/login`.
3. Authenticated non-admin access to `/admin/*` redirects to `/dashboard`.
  </verify>
</task>

<task type="auto">
  <name>Task 2: Embed app admin UI and sync auth context</name>
  <files>
    landing/src/pages/admin/AdminDashboardEmbed.tsx
    client/src/main.ts
  </files>
  <action>
1. Create an admin embed page in landing that computes the target app admin URL from `VITE_CLIENT_APP_URL` and current route suffix.
2. Render the app admin route in a full-height iframe and keep a direct "open full admin app" link.
3. Send `clippster-auth-sync` postMessage payload (token/user/provider) from landing iframe host to app iframe.
4. Add a message listener in `client/src/main.ts` that accepts allowed-origin auth sync, stores auth values, and triggers auth store refresh.
  </action>
  <verify>
1. `client` build passes (`yarn build`).
2. Embedded admin route receives auth sync and stays authenticated.
3. Route suffixes like `/admin/users`, `/admin/organizations/:id` resolve to same app admin pages in iframe.
  </verify>
</task>
